# SEO pages (`/seo`)

Server-side-rendered (SSR), crawlable "big-text" pages that expose the
**Word Map** and **Han Map** per-language content as standalone HTML. The
interactive apps render their language popups in JavaScript, which search
engines don't index well; these PHP pages publish the same data as real,
localized, crawlable text plus rich internal linking.

**Live example:** `https://langmap.heuron.com/en/wordmap/ja`

---

## URL scheme

```
/{ui}/wordmap/{lang}     a single Word Map language page
/{ui}/hanmap/{lang}      a single Han Map language page
/{ui}/wordmap/           Word Map language index (hub)
/{ui}/hanmap/            Han Map language index (hub)
/{ui}/                   per-UI-language hub
/sitemap-seo.xml         dynamic sitemap (all langs × all UI prefixes + hreflang)
```

- `{ui}` is one of the **19 UI languages**: `en ja ko zh yue vi th id hi de fr it es pt ru uk ar he sw`.
- `{lang}` is a Word Map / Han Map language code (see `docs/words/LANG_CODES.md`).
- Any non-prefixed legacy path (`/wordmap/{lang}`, `/`, …) **301-redirects** to its `/en/…` equivalent. The canonical URL is always the UI-prefixed one, with `<link rel="alternate" hreflang>` for all 19 UI langs + `x-default`.

## Build (data export)

The JS data files are the **single source of truth**. A Node step loads them
in a `vm` context (exactly as the browser does) and emits canonical JSON the
PHP reads:

```bash
node tools/export_seo_data.js
# → data/wordmap_seo.json
# → data/hanmap_seo.json
```

Re-run it whenever any of these change: `wordmap_data.js`, `words/*.js`,
`wordmap_meta.js`, `hanmap_data.js`, `lang_names.js`, `data.js` (word-order
sentences). The generated `data/*_seo.json` are **committed** so a production
host without Node can still render (treat them as build output, regenerated by
the exporter — never hand-edit).

## Run locally

Requires PHP (CLI). `php-mbstring` is recommended but not required (a pure-PHP
polyfill is included for minimal installs).

```bash
sudo apt-get install -y php-cli php-mbstring   # if needed
node tools/export_seo_data.js                  # build the JSON
php -S localhost:8080 router.php               # serve (clean URLs + static passthrough)
```

Then open e.g. `http://localhost:8080/ja/hanmap/zh`. The dev server also serves
the static `.html` apps, so the SEO pages' reverse links and the apps' forward
links resolve on the same origin.

## Files

| file | role |
|------|------|
| `tools/export_seo_data.js` | Node exporter: JS source → `data/{wordmap,hanmap}_seo.json` (incl. word-order from `data.js`). |
| `index.php` | front controller: parse `{ui}`, route, 301 legacy/`/`, render hubs / 404. |
| `router.php` | shim for PHP's built-in dev server (clean URLs + static files). |
| `.htaccess` | Apache rewrite (production). |
| `seo/lib.php` | shared helpers: JSON loader, `SEO_T` 19-lang label table, `seo_head()` (title/meta/og/hreflang/canonical/webfonts/picker/popup), the char table, the related-language comparisons, related-links, sitemap helpers, the language-switch JS. |
| `seo/wordmap.php` | Word Map language page + index. |
| `seo/hanmap.php` | Han Map language page + index. |
| `seo/sitemap.php` | dynamic `/sitemap-seo.xml`. |

## What each language page contains

- **Localized chrome + body** in the page's UI language (titles/meta/OG,
  section headings, the description and language name from the data). Meta chip
  **values** (family, speakers, region, script, official, ISO 639-3, Glottocode,
  vitality, romanization, "also known as" aliases) stay in their native form.
- **Han Map char table** — an aligned dictionary table (Character | Gloss |
  Reading-type | Form | IPA) showing every character's reading(s), including
  文白異讀 / 呉音漢音 multiple readings (sourced from `HAN_VARIANTS`).
- **Compare with related languages** — three sections (Words / Word order / Han
  readings):
  - Words & Han readings: the page's language vs sibling languages, **ordered by
    IPA similarity** (mean 1−normalized-Levenshtein over shared items), paginated.
  - Word order: two blocks (major world languages / closest relatives) under one
    sentence picker, with **LangMap-style SVG connector lines** linking same-role
    segments across language rows. The first 10 sentences are SSR'd; the rest are
    lazy-rendered client-side from a JSON blob (keeps the page light).
- **Internal links** — sibling/cross-map links to other SEO pages, a link to
  open the language in the interactive map, and an embedded Leaflet map.
- **Language-switch popup** — first-visit suggestion to switch to the visitor's
  browser language; returning visitors auto-redirect to their stored choice; a
  pulldown switches UI language. Pure client JS (`localStorage.langmap_ui_pref`).

The interactive apps (`wordmap.html`, `hanmap.html`, `index.html`) link **into**
these pages from their per-language popups / selector.

## Deploy notes

- Needs PHP on the host. Point the rewrite (`.htaccess`) at `index.php`.
- Commit `data/*_seo.json` (production likely has no Node); regenerate with the
  exporter whenever the underlying JS data changes.
- Webfonts (Gentium Plus / Charis SIL / Noto Serif CJK) are loaded from Google
  Fonts so romanized diacritics and Han glyphs render consistently.
- Translations of the UI chrome (`SEO_T` in `seo/lib.php`) are first-pass for
  several of the 19 languages — refine as needed.
