# Review 456 — Lang Map（語順・文）のデータ（全体ラリー2／10）

**日付:** 2026-08-27
**切り口:** 3つ目の地図。100文 × 223言語、各文が色分けされた統語成分 A–K を持ち、
言語ごとにその並び順が違う、というデータ。455 と同じ汚染の切り口をまず当てる。

## 汚染 — 1件も無い

223言語について、100文分の「成分＝語」列を連結した署名を作って総当たりした。

- **全100文が完全一致するペア: 0組**
- **90文以上一致するペア: 0組**

Han Map で6行のコピーが出た直後だけに念入りに見たが、Lang Map は
**スペイン語8変種・ポルトガル語2変種を含めても一致ゼロ**。語順データは
語彙と違って変種ごとに必ずどこかが動くので、コピーがあれば即座に出る。無い。

## 記法を3つ取り違えた（すべて設計どおり）

最初の probe は 14,931件の「異常」を出したが、全部私の無知だった。

| 見えたもの | 実際 |
|---|---|
| 未宣言の成分 `A|B`・`F|G`（1443件） | **融合成分**。1語が2つの成分を担う（sw `niliyoiona` = F+G、fi `Haluaisin` = A+B）。`app.js` が `split('|')` で両方の色を縞に描く |
| 同じ成分が2回（385件） | **不連続構成素**。en `is … delicious` は両方 D で、間に C `very` が割り込む。語順地図が見せたいものそのもの |
| 成分の欠落（13,103件） | その言語がその成分を持たない。ja が主語を落とす類 |

成分IDを `|` で分解して数え直すと、**未宣言の成分参照は0件**。
テキスト中の `|` は egy(418) と sux(431) だけで、これは字形と翻字の対（別用途）。

宣言済みで誰も使わない成分が3件（s14 の H、s50 の B、s95 の F）出たが、
これは既存の `tools/langmap_role_check.js` が `UNUSED_ROLE` として
**すでに informational で把握済み**。作者の判断なので触らない。

## 発見 — 4行が生のコードのまま表示されていた

`es_eu` `pt_eu` `myn` `ine` の4言語に、**19UIのどれにも名前が無かった**。
`langName()` は最後にコード自身を返すので、読者の画面には

> Spanish (Mexico) … **es_eu** … Portuguese (Brazil) … **pt_eu**

と、兄弟だけ名前があって当人が生コードで並ぶ。オーナーが以前指摘した
「一部言語名が英語のままです」と同じ病気の、もう一段悪い版。

### 原因 — coverage ガードが3つ目の地図を見ていなかった

`tools/lang_name_coverage.js` の冒頭には「every language on **either map**」とある。
書かれた時点では地図は2つで、実際に読んでいるのも `LANG_DATA`（Word Map）と
`HAN_LANGS`（Han Map）だけ。**Lang Map の `SENTENCES` は対象外**だったので、
4行が抜けたままガードは緑を出し続けていた。

### 名前は作らず、既にあるものを使った

| コード | 正体 | 根拠 |
|---|---|---|
| `myn` | **ユカテコ・マヤ語** | `in k'aba' Tanaka -e'` の所有接頭辞 `in-` と話題標識 `-e'`。K'iche' なら `nub'i'`、Mam なら `nbi'` |
| `ine` | **印欧祖語** | `*mene *h₁nómn̥ Tanaka *h₁ésti` |
| `es_eu` | 欧州スペイン語 | `Este café está muy bueno` |
| `pt_eu` | 欧州ポルトガル語 | `O meu nome é Tanaka`（所有詞の前に定冠詞＝EP。BP は `Meu nome é`） |

`myn` と `ine` は、**同じ言語がこのファイルに既に `yua`・`p_ine` として
19UI分の名前を持っている**。訳語を新たに作らず、その文字列をそのまま流用した。
`es_eu`/`pt_eu` は兄弟の書式（`Spanish (Argentina)` / `スペイン語(アルゼンチン)`）に合わせた。
限定辞は「(スペイン)」ではなく **「(欧州)」** — コードが `_eu` である上に、
(Spain) では id `Spanyol (Spanyol)`・th `สเปน (สเปน)`・vi `Tiếng Tây Ban Nha (Tây Ban Nha)` と
言語名が2回出て読めなくなる。

**計76文字列（4コード × 19UI）。** ガードは Lang Map を読むよう拡張した
（`myn` を一時的に消す → `Lang Map myn — no en name` で検出、戻して0を確認）。

## 共有テキストが読者の言語を無視していた

`getShareText()` は `LangMap: ${sentence.title}` を返していた。
`sentence.title` は **1〜25番が英語、26〜100番が日本語**なので、
どのUI言語の読者が共有しても、この2言語のどちらかが出る。

一方 `sentenceLabel()`（文の選択肢）は既に正しく、
**読者のUI言語の文そのもの**を使っている。同じ方式に揃えた。
文は223行すべてに存在するので、追加のデータは要らない。

## 誤警報を2件、自分で潰した

- **「242言語と書いてあるが実データは223」** → `app.js` の `LANGUAGES` roster は
  **242 で正しい**。差の19（`ja_kanbun` `zh_wenyan_edu` `vi_han` `sa_edu` `pi_edu`
  `fa_clas` `ar_qur` `he_mis` `de_lut` `en_em` `gd` `it_dan` `fr_class` `es_sgl`
  `el_kath` `hy_grab` `se` `to` `xct_litpr`）は文データ未着手の行で、
  UI に `pending`（準備中）文字列が用意されている。設計どおり。
- **「文タイトルが英日混在で選択肢に出る」** → 選択肢は `sentenceLabel()` が
  読者の言語の文から作るので、タイトルは最後のフォールバックにしか使われない。
  実害があったのは共有テキストだけで、それは上で直した。
